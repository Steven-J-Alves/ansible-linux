# Conventions

This project follows the `ansible-project-builder` standard. If you are an agent (or person) working on this repo without that skill loaded, follow the rules below — they encode decisions made once so they do not need to be re-litigated per pull request.

## Structure

- `roles/baseline_*`: one thin role per OS-level domain (SSH, firewall, kernel, systemd, users, etc.). **Never** a single monolithic `baseline` role that does everything.
- `inventories/{dev,staging,production}/`: one inventory directory per environment. **Never** a single flat inventory file when there are multiple environments.
- `group_vars/` at project root has `all.yml` + `debian_family.yml` + `redhat_family.yml` — distro-specific overrides live here, not scattered inside role tasks.

## Multi-distro

- Roles dispatch by `ansible_os_family` (`Debian.yml` vs `RedHat.yml`), **never** by `ansible_distribution` string checks. New distros of the same family (Rocky → AlmaLinux → RHEL, Ubuntu → Debian) share the family branch for free.
- Declared distros: **Ubuntu 24.04, Debian 12, Rocky 9, Amazon Linux 2023**. Each is a Molecule scenario per role.

## Naming

- Roles: `baseline_<snake_case>` — the `baseline_` prefix groups them and avoids collision with future non-baseline roles.
- Variables: prefixed `baseline_<role_name>_` (e.g. `baseline_ssh_port`, not `ssh_port`) — bare names collide across roles.
- Files: snake_case. Roles use canonical filenames (`defaults/main.yml`, `tasks/main.yml`, `handlers/main.yml`, `meta/main.yml`).

## Versioning

- `ansible-core`, `ansible-lint`, `molecule`, `molecule-plugins` and every collection in `requirements.yml` are pinned with `==` to the latest stable at project creation (or the last deliberate bump). **Never** `>=` or `~>` — reproducibility is the whole point.

## Testing

- Every role has Molecule scenarios for the four declared distros, under `roles/<name>/molecule/<distro_scenario>/`.
- `molecule test` sequence includes `idempotence` — the second converge must be `changed=0`.
- `verify.yml` may run Lynis and assert a minimum hardening score (default 75, overridable via `baseline_lynis_min_score`).

## Docs

- `docs/categories.md` classifies every parameter into one of five boxes: DEFAULT / RECOMMENDED / ENVIRONMENT-DEPENDENT / SECURITY-HARDENED / PERFORMANCE-TUNED. Blocks blind CIS-cargo-culting.
- `docs/rollback-procedures.md` has one section per role: what changed, how to undo, where the backup lives, how to validate the rollback.
- `docs/runbooks/` holds troubleshooting guides written on demand.

## Secrets

- `ansible-vault` for secrets — never in plain YAML. Vault password comes from `.vault_pass` (gitignored) or `ANSIBLE_VAULT_PASSWORD_FILE`.
- No secrets in `inventories/*/hosts.yml`, no secrets in `group_vars/all.yml` (public) — all secrets in vault-encrypted files under `inventories/<env>/host_vars/` or `inventories/<env>/group_vars/`.

## Execution

- `ansible-lint`, `yamllint`, `ansible-playbook --syntax-check`, `ansible-playbook --check --diff`, `molecule test` (Docker driver) — safe, run freely.
- `ansible-playbook` (real apply) — **never automatically**. Only when a human asks explicitly.
- `molecule test` in a scenario using a cloud driver (EC2, Hetzner, GCE) — **ask before running**, that spawns real infrastructure with a cost.

## Language

- All code, comments, and documentation in English.
- No author bylines (`# Author: ...`, `## By ...`) in any file — `git log` is authoritative.
